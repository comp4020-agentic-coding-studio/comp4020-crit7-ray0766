# Crit 7

The breakthrough was a number I didn't like. The demo plan was four full
semesters, 96 units placed, and the tally said 90 of them counted. My first
instinct was that the progress rule was wrong. It wasn't: the Master of
Computing takes COMP8715 twice, and my own schema had a unique index that said
a course goes in a plan once. The data was telling me something true about
the program that I had quietly overruled in the table. The fix was a
migration, not a patch to the rule, and the demo went to 96.

That is the first time an app of mine has corrected me with data I had
transcribed rather than made up. It only happened because the harness said
"never invent a requisite": every line came from a Programs & Courses page
with the URL beside it, and where the page was odd — COMP8830 still asking
for a course that no longer exists — the planner was allowed to be odd with
it. A made-up catalogue would have been tidier and would have taught me
nothing.

Crit 5 taught me that a model can be correct and the game still wrong, and
that I had to play it to find out. This week's version is that code can be
correct and the data still false, and no test of the code will say so. So the
developer I want to be transcribes before assuming, keeps the transcript's
gaps visible ("not checked") instead of smoothing them, and treats a number
that looks wrong as the moment to look harder, not to reach for the rule.
